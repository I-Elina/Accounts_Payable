🏛️ Section 1: Enterprise Architecture Pillars

The system is designed following modern financial automation best practices, ensuring zero regulatory or audit vulnerabilities:

[ User Upload (.csv / .xlsx) ] │ ▼ [ FastAPI Ingestion: POST /api/uploads ] ──► Emits: UPLOAD_RECEIVED │ ▼ [ Deterministic Engine Boundary: run_engine ] ├─► Pass 1: R01-R08 (Missing, Invalid, Dates, Mismatch, Exact Dup, Policy) └─► Pass 2: R09-R11 (Fuzzy Duplicates with Gate, Outliers) │ ▼ [ SQLite ACID Persistence ] ──► Emits: INGESTION_COMPLETED & INVOICE_FLAGGED ├─► uploads (Batch records) ├─► invoices (Canonical fields) ├─► decisions (Score, evidence JSON, review status) └─► audit_log (Immutable append-only trail) │ ┌──────┴───────────────────────────────────┐ ▼ ▼ [ AI Explanations: POST .../summary ] [ Conversational Assistant: POST /api/chat ] ├─ Multi-LLM: Mock / Azure / Gemini ├─ Read-only Tool Registry ├─ Zero-Decision Mandate ├─ DB-Generated Cards (No LLM Text) └─ Anti-Hallucination Regex Guard └─ Human-in-the-Loop Proposal Bar
Enterprise Compliance Guarantees (SOX & Financial Integrity):
  • Deterministic Authority: Financial routing is 100% deterministic code. Generative LLMs are mathematically prevented from changing invoice decisions, approving disbursements, or modifying ledger entries.
  • Immutable Audit Trail: Every single state change is recorded in audit_log with UTC ISO-8601 timestamps and unambiguous actor attribution (engine, ai, user, system).
  • Zero-Mutation Chat Proposing: When a user asks the chatbot to "Approve INV-1042", the assistant only returns a visual proposal. Zero bytes are written to the database until a human reviewer physically clicks the confirmation button.
  • Spreadsheet Formula Injection Defense (CSV DDE): In compliance with OWASP guidelines, text cells beginning with =, +, -, or @ are sanitized with a leading apostrophe ' to prevent Excel formula execution attacks.

🗄️ Section 2: Database Schema & Relational Specifications

Engineered with SQLite for instant embedded execution and 100% compatibility with PostgreSQL.

Tracks uploaded invoice batches, row metrics, and cross-batch history options.

Column Type Key Description
idINTEGERPRIMARY KEYAuto-incrementing batch identifier.

🧩 Section 3: Complete Backend Function Directory

Every service and router module implemented in backend/:

Database Layer backend/database.py
  • get_conn(db_path=None) -> sqlite3.Connection: Opens thread-safe connection with PRAGMA foreign_keys = ON; and sqlite3.Row factory.
  • init_db(db_path=None) -> None: Reads and executes schema.sql, sets default settings if empty.
  • row_to_dict(row) -> dict | None: Converts SQLite Row object to clean Python dictionary.
Upload & Ingestion Pipeline backend/services/upload_service.py
  • process_upload(file, uploaded_by=None, use_history=False) -> UploadResponse: Orchestrates file storage, engine execution, database insertion, and individual invoice audit event logging.
  • _run_engine_or_stub(file_path, history, config) -> dict: Invokes Member 1's decision engine with seamless fallback to contract mock JSON if engine is still in progress.
  • list_uploads() -> UploadListResponse: Returns all past uploads sorted by most recent.
Invoice Query & Detail Service backend/services/invoice_service.py
  • list_invoices(...) -> PaginatedInvoicesResponse: High-performance SQL query with parameterized filtering (decision, exception_type, review_status, confidence range, full-text search) and pagination.
  • get_invoice_detail(invoice_pk) -> InvoiceDetailResponse: Joins invoice and decision records, fetches matching duplicate record if present, and appends review history.
Review & Conflict Workflow backend/services/review_service.py
  • submit_review(invoice_pk, review_req) -> InvoiceDetailResponse: Enforces that invoice is in pending status, rejects duplicate reviews with HTTP 409 Conflict, updates decision to approved/rejected, and logs REVIEW_APPROVED/REVIEW_REJECTED audit events.
Dashboard Aggregation Service backend/services/stats_service.py
  • get_stats(upload_id=None) -> StatsResponse: Computes total counts, decision breakdown, auto-pass rate, exception frequency, 10-bucket histogram (0.0-0.1 ... 0.9-1.0), and estimated minutes saved (5 mins per auto-pass).
Formula-Safe Report Export backend/services/report_service.py
  • generate_report_csv(upload_id, decision=None) -> io.BytesIO: Generates streaming CSV with UTF-8 BOM (\ufeff) for Indian Rupee symbol support in Excel. Escapes formula characters (=, +, -, @) with a leading single quote.
  • _escape_cell(val) -> Any: Prevents CSV Formula Injection attacks.
Immutable Audit Trail Service backend/services/audit_service.py
  • log_event(actor, actor_type, event_type, invoice_id=None, upload_id=None, details=None, conn=None) -> int: Appends an immutable audit event to SQLite. Supports transactional re-use.
  • get_audit_events(upload_id=None, invoice_id=None, event_type=None, page=1, page_size=25) -> PaginatedAuditResponse: Paginated query for audit logs, ordered newest first.
Configuration & Threshold Service backend/services/config_service.py
  • get_current_config() -> ConfigResponse: Reads threshold settings from the database and returns the full 11-rule catalogue.
  • update_config(update_req) -> ConfigResponse: Validates 0 ≤ exception_below < auto_pass_threshold ≤ 1, updates settings, and logs SETTINGS_CHANGED in audit log.
Chat Assistant & Non-Mutating Tools backend/services/chat_service.py & backend/ai/tools.py
  • process_chat_message(chat_req) -> ChatResponse: Intent matching, tool execution, verified card rendering, and proposal handling.
  • TOOL_REGISTRY: Read-only functions (get_invoice, explain_decision, list_pending, list_exceptions, list_duplicates, get_stats, get_audit, get_report_link, propose_review).
  • propose_review(invoice_id, action): Returns a visual UI proposal bar. Never writes to database!
AI Explanation & Anti-Hallucination Guard backend/ai/summary.py & backend/ai/validate.py
  • generate_summary(decision_record) -> dict: Multi-provider summary generation supporting mock, azure, and gemini.
  • validate_summary(output, record) -> bool: Validates that summary is ≤ 3 sentences, ≤ 600 chars, suggested action is valid, and every token matching invoice ID format exists in verified input facts.

🚀 Section 4: Enterprise Production Scaling & Security

Postgres / Azure Cloud Production Roadmap:
  1. Database Migration: The schema uses standard ANSI SQL types. Transitioning to PostgreSQL or Azure SQL requires only replacing backend/database.py with an async SQLAlchemy connection pool (e.g. asyncpg).
  2. Asynchronous Processing: For files larger than 10,000 rows, file parsing can be offloaded to Celery / Redis background worker queue while the API returns an immediate 202 Accepted with job tracking.
  3. Multi-LLM Resilience: Supports Google Gemini 1.5/2.5 Flash, Azure OpenAI GPT-4o, and an offline deterministic fallback with zero disruption if API quotas are exhausted.
